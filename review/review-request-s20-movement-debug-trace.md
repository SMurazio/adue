# REVIEW REQUEST: S20 Movement Debug Trace

## 1. INTENT & SCOPE

This branch implements `todo/S20-movement-debug-trace.md`: a flag-gated end-to-end movement trace that can distinguish server tick hitches caused by scheduler/timer gaps from GC pauses, and can follow one watched/admin `MoveStep` from client send to server validation, snapshot carry, and client confirmation. Scope is instrumentation only: no protocol change, no prediction, no pathfinding, no LOS, no movement behavior change. ## 4. DECISIONS & DEVIATIONS

- I did not bump protocol or add the optional last-processed input sequence echo to `WorldSnapshot`; the timestamped trace gives send -> validate -> snapshot -> confirm correlation without changing wire contracts.
- Tick hitch tracing is global when `MMO_DEBUG_MOVEMENT=1`; per-step and per-snapshot tracing is limited to admin sessions or names/character ids in `MMO_DEBUG_MOVEMENT_WATCH`.
- Snapshot-carry trace logs once per recipient packet carrying the watched entity. This is intentionally verbose only under the debug flag.
- The headless capture surface is a script-generated `.run` console harness rather than a committed project. This keeps normal solution/build surface smaller and follows existing `.run` script pattern used by review stress metrics.
- Client debug state updates only when `MMO_DEBUG_MOVEMENT` is enabled, to keep normal runs close to zero overhead.
- I added `MMO_DEBUG_MOVEMENT_WATCH` and `MMO_DEBUG_MOVEMENT_HITCH_MULTIPLIER` beyond the minimum single flag because S20 explicitly asked for watched/admin scoping and a threshold. Defaults preserve normal behavior.
- No gameplay, prediction, pathfinding, LOS, rollback, or process-split work was introduced.

## 6. KNOWN GAPS / TODOs / LOW-CONFIDENCE AREAS

- The optional exact per-step server echo was deliberately not implemented. If timeline timestamps are not enough in real debugging, add a new Orchestrator todo for protocol-level input-sequence echo.
- The Godot overlay is intentionally compact text, not a chart or panel. It may need UI polish later if humans use it frequently.
- The headless harness emits many useful trace lines but is still a script-generated scenario, not a long-lived test project.
- Client `render=` in the confirmation trace is the render position at snapshot-confirm time. It does not prove the subsequent visual glide unless the render loop samples after confirmation; that is why Godot overlay/build still matter.
- The tick hitch trace can allocate strings when enabled. It should be zero-normal-spam when disabled, but review the disabled hot path carefully.
- S20 was untracked locally, so the completed todo deletion is not visible in the commit diff.
