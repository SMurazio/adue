## 4. DECISIONS & DEVIATIONS

- S18 write-behind uses a dedicated `PersistenceWriteBehindWorker` with `ConcurrentQueue` + `SemaphoreSlim`, not a full typed server-event bus. Reason: task asked for the smallest write-behind/async queue; typed events remain a future refactor in `docs/architecture.md`.
- S18 periodic checkpoint tracks latest dirty tile per durable character in a dictionary and clears after enqueue. This intentionally coalesces repeated movement before checkpoint.
- S18 shutdown calls `QueueConnectedPlayersForPersistence()` then awaits a bounded worker flush. Disconnect still enqueues instead of blocking the sim path.
- S18 tests assert that a post-move tile is persisted, not that the exact client-observed tile is persisted. Reason: under parallel test load the server can accept another move before the client observes it; exact equality made the test scheduler-sensitive while not strengthening the durability guarantee.
- S19 uses the recommended kick-old policy. It removes/despawns the old session before spawning the new one, queues a save for the old tile, returns the old network id, then disconnects the old peer.
- S19 originally tried to assert a reliable `ServerErrorMessage` reaches the old peer before disconnect. That was removed because reliable delivery is not guaranteed once we immediately disconnect. The test now asserts the acceptance criteria: old session disconnected, new same-character session active, one visible duplicate entity.
- N14 did not remove `MmoClient.Entities` or `GetRenderStates()` because tests/diagnostics still use them. It adds `EntityCount` and `CopyRenderStatesTo(...)`, and moves Godot to the allocation-light path.
- N15 adds `InternalsVisibleTo` and an internal outbound sink for tests. This is a test seam only; production sends still go through LiteNetLib.
- N15 placeholder expiry uses `PlaceholderSnapshotTtl = 60` applied on incomplete snapshots. This bounds bogus metadata while allowing delayed spawns to self-correct.
- Protocol version did not change. This queue changes client behavior around acks/placeholders/interpolation but does not change wire contracts.

## 6. KNOWN GAPS / TODOs / LOW-CONFIDENCE AREAS

- The persistence worker is intentionally simple and unbounded. It coalesces dirty tile marks before checkpoint but does not coalesce queue entries after enqueue. Under severe DB stalls, queue-depth metrics/backpressure should be a future todo.
- Shutdown flush is bounded and best-effort. A hard process kill can still lose up to the configured checkpoint interval plus any queued-but-not-flushed save.
- Duplicate-login old-peer error delivery is best-effort and not asserted. If UX requires a visible "logged in elsewhere" message, the policy needs a graceful disconnect delay or protocol-level disconnect reason.
- `PlaceholderSnapshotTtl = 60` is a client implementation constant, not a negotiated server value.
- The internal test seam in `MmoClient` is intentionally minimal; reviewer should check it cannot change production behavior.
- Existing uncommitted working-tree noise was present before this unit and is not part of this review: `docs/networking-design-plan.md`, older deleted review files, `todo/S17...`, `.claude/settings.local.json`, `docs/godot-client-design.md`, `docs/worldstate-zone-design.md`, `review/README.md`, `src/Mmo.Client.Godot/MmoClientRoot.cs.uid`, `start-mmo.cmd`.
